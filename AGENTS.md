# Инструкции для Codex и участников GoodsAI

1. Сначала прочитай [docs/PROJECT_STATUS.md](docs/PROJECT_STATUS.md), проверь ветку,
   `git status --short --branch` и существующие незакоммиченные изменения.
   Далее читай только документы, исходники и тесты своей задачи по карте модулей.
2. Текущий проект — Python CLI, baseline E1. Не повторяй полный EDA без конкретной
   причины; используй существующие отчёты/manifests. Продуктовые презентации и
   старые планы не являются доказательством реализации или обязательным дизайном.
3. Соблюдай текущий контракт v0.1. Общие изменения форматов, единиц, категорий,
   confidence/decision и интерфейсов согласовывай до реализации.
4. Extractor получает только text-only вход. Не передавай готовые target params,
   vendor/model/gold/clicks как подсказки и не подставляй ответ по SKU. Метаданные
   для split и слабые метки держи отдельно от входа и независимой gold-оценки.
5. Не изменяй оригиналы `data/raw/`. Pickle другого происхождения не загружай без
   подтверждения доверенности. Данные, разметка, predictions, окружения и секреты
   не входят в Git; реальные данные не копируй в tests и не отправляй внешним API.
6. Работай в feature-ветке, передавай изменения через PR. Не меняй main, не делай
   force push и не теряй чужую работу. Commit, push, PR/merge, доступ к VM и
   обращения к моделям выполняй только в явно разрешённом объёме текущей задачи.
7. Перед завершением запускай относящиеся тесты. Для общих модулей baseline:
   `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`.
   Для reader: `.\.venv\Scripts\python.exe -m unittest discover -s scripts/research -p 'test_*.py' -v`.
   Для чистой документации достаточно проверки ссылок/примеров/CLI; тяжёлые прогоны не нужны.
8. Coverage не равно precision/F1. Confidence сейчас — heuristic score, не
   калиброванная вероятность; все кандидаты review. Без ручного gold качество N/A.
   Evidence подтверждает источник фрагмента, но не гарантирует истинность значения.
9. Сообщай, что изменилось, какие проверки реально выполнены, результаты и
   ограничения. Отделяй локальный Windows-прогон от непроверенного Linux/VM.
10. После существенных изменений обновляй PROJECT_STATUS.md в рамках задачи;
    не создавай автоматические hooks или инфраструктуру без согласования.
