# Запись и восстановление outputs (R3)

Команды CLI и формат prediction v0.1 сохранены. Меняется публикация локальных
файлов, не извлечение/нормализация и не confidence. Это реализация из ветки
`feature/vlad-atomic-output`; ВМ этим этапом не обновляется.

## Обычная работа

Одиночные JSON/JSONL пишутся в уникальный tempfile рядом с назначением, затем
заменяются os.replace. Ошибка до замены сохраняет старый файл. Запись и чтение
пары используют неблокирующие OS-блокировки. Второй процесс получает
`Output is busy: ...; retry after the other process finishes`; разные output
работают независимо, кроме случаев общего manifest basename.

Windows использует [msvcrt.locking](https://docs.python.org/3.12/library/msvcrt.html#msvcrt.locking),
POSIX — [fcntl.flock](https://docs.python.org/3.12/library/fcntl.html#fcntl.flock).
ОС освобождает блокировки при завершении процесса. Пустые служебные файлы
`.имя.goodsai.lock` остаются намеренно: их удаление при работающих процессах
может создать независимые блокировки. Наличие lock-файла не означает занятый output.
Новые служебные имена исключены Git глобально.

Predict сначала вычисляет новые predictions и manifest в приватном staging,
проверяет hash, сохраняет предыдущие файлы и журнал prepared, заменяет оба файла
и записывает committed. Reader/writer при следующем обращении завершает уборку
committed либо восстанавливает прежнюю пару для prepared. При первой записи
откат удаляет незавершённую пару, потому что предыдущих файлов не было.
При обычном исключении откат выполняется сразу; при kill — при следующем
поддерживаемом обращении. До committed результат не считается опубликованным.

## Проверить или восстановить конкретную пару

Из корня проекта, Windows PowerShell (подставить путь своего output):

```powershell
.\.venv\Scripts\python.exe -c "from pathlib import Path; from goodsai.data import read_predictions; print(sum(1 for _ in read_predictions(Path('outputs/my-card/predictions.jsonl'))))"
```

Linux:

```bash
.venv/bin/python -c "from pathlib import Path; from goodsai.data import read_predictions; print(sum(1 for _ in read_predictions(Path('outputs/my-card/predictions.jsonl'))))"
```

Будет прочитано число JSONL-строк только после восстановления и сверки SHA
с manifest, если manifest существует. Пустой/повреждённый manifest или неверный
SHA дают ошибку; повреждённые backup/журнал не принимаются за успешный результат.
Нужны права создавать lock-файлы и при необходимости восстанавливать output.
Старые standalone predictions без manifest остаются читаемы, но не называются
проверенной парой. JSONL parsing и hash не заменяют проверку схемы/evidence.

`goodsai.cli evaluate` при наличии gold использует этот reader, затем обычную
схемную/семантическую проверку. Без gold он по-прежнему возвращает N/A и не
обещает проверить predictions. В Python можно использовать `read_predictions`
или контекст `goodsai.storage.prediction_snapshot` и прочитать файл внутри него.
При досрочной остановке генератор reader необходимо закрыть, чтобы снять lock.

При `Prediction recovery failed` сохранить `.goodsai-transaction.json` и
указанный в нём приватный `.goodsai-txn-*` каталог для диагностики. Не удалять
их ради повторного запуска: там может быть единственная резервная копия.
Повторная запись того же output тоже останавливается до успешного восстановления.
При `Output is busy` дождаться реального окончания владельца; PID-файла и
ручного снятия «устаревшей блокировки» здесь нет.

## Границы

Два отдельных файла невозможно заменить одной атомарной операцией. Сторонний
reader без блокировки может увидеть переходное состояние. Для согласованного
чтения нужен наш reader/context; простое cat не является такой проверкой.
Сторонние писатели, редакторы, ручное удаление lock/журнала и неподдерживаемые
файловые системы не входят в гарантию. Выбирать обычные локальные файлы output.

После kill до записи prepared могут остаться неиспользуемые приватные staging
каталоги; старые целевые файлы в этот момент не менялись. Такие каталоги не
считаются результатами. Они не удаляются автоматически по одному лишь имени.
Уникальный tempfile одиночной записи убирается при исключении либо следующим
писателем этого назначения под блокировкой. Отключение питания/сетевые FS не
проверены. fsync применяется к файлам, на POSIX также к каталогам; Windows
реализация проверена отдельно от пока не проверенной POSIX-ветки.

R3 защищает одиночные записи и пару predict/manifest. Он не делает одну общую
транзакцию из prepare/input/provenance или всего комплекта demo/summary.
Исторические результаты не пересчитывались. План и тесты:
[atomic_output_plan](../research/atomic_output_plan.md),
[test_storage.py](../../tests/test_storage.py).
