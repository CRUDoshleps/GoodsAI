   Не понижать требование проекта и не заменять системный Python вслепую.

3. Конфликт untracked `.gitignore` устранён с сохранением правил и backup.
   Не применять `git clean/reset --hard` для последующих обновлений.
4. По диску явного дефицита нет. CPU/RAM, данные, процессы,
   порты и manager сервиса ещё не проверены. Python, установка зависимостей
   и чтение Gitea на ВМ уже подтверждены.
5. Следующий шаг — обычный прогон pipeline и уточнение официального интерфейса

## Выполненные пользователем команды установки Python

Способ сверён с официальными инструкциями Astral:
[установка uv](https://docs.astral.sh/uv/getting-started/installation/),
[путь установки и запрет правки shell profile](https://docs.astral.sh/uv/reference/installer/),
[managed Python](https://docs.astral.sh/uv/guides/install-python/).
Это пользовательская установка инструмента и интерпретатора, не установка
GoodsAI и не deployment. Git checkout и данные проекта не изменяются.

```bash
goodsai_uv_installer="$(mktemp)" &&
curl --proto '=https' --tlsv1.2 -LsSf https://astral.sh/uv/install.sh -o "$goodsai_uv_installer" &&
UV_INSTALL_DIR="$HOME/.local/bin" UV_NO_MODIFY_PATH=1 sh "$goodsai_uv_installer" &&
"$HOME/.local/bin/uv" --version &&
"$HOME/.local/bin/uv" python install 3.12 &&
goodsai_python="$("$HOME/.local/bin/uv" python find 3.12)" &&
"$goodsai_python" --version &&
python3 --version
```

Пользователь передал успешный вывод: uv 0.13.1, Python 3.12.15 по найденному
пути и прежний Python 3.10.12 для `python3`. На этом первом этапе установлены
только инструменты; последующая установка GoodsAI и tests описаны в начале документа.
При повторении не отключать TLS и не продолжать после ошибки; точные версии
будущих установок могут отличаться, сохранять фактический вывод.

## Что ещё не проверено и какой контракт ожидается

Для нового окружения через uv использовать `uv venv --python 3.12 --seed .venv`,
если следующий шаг — `python -m pip install -e .`: seed обеспечивает pip.
Обычный `uv venv` без seed не гарантирует наличие pip. Исправление инструкции
теперь подтверждено успешной установкой GoodsAI на ВМ.

Commit, окружение, установка и tests уже зафиксированы. По последнему сообщению
администраторов на выходные требуется решение на **8000** и весь код в main;
ручки/транзакции обещаны в понедельник вечером. Следующий шаг — установка
HTTP-extras и постоянный запуск [временного адаптера](http_service.md).
Последующая диагностика пользователя подтвердила systemd PID 1, работающий
user manager, Linger=no и свободный TCP 8000. Подготовлен пользовательский
unit; включение linger, установка и HTTP-доступность ещё не подтверждены.
На момент этой
записи на ВМ подтверждены только прежние 18+3 CLI/reader tests, не HTTP-тесты
и не работающий сервис.
