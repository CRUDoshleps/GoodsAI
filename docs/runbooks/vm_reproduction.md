## Выводы и следующий шаг

1. Текущий `python3` не удовлетворяет `requires-python >=3.12` из проекта.
   Пользователь установил uv 0.13.1 и managed CPython 3.12.15 без sudo,
   подмены системного Python и правки shell profile. Версии подтверждены
   переданным выводом. Предупреждение о PATH ожидаемо: использовать полный
   путь `~/.local/bin/uv`. Отдельное окружение GoodsAI ещё не создано.
   Не понижать требование проекта и не заменять системный Python вслепую.
2. Checkout не содержит рабочего baseline. После пользовательского fetch,
   зафиксировавшего прежний серверный `6fe9ea0`, публикация в Gitea main
   выполнена через PR #2/#3. Теперь нужен новый fetch и fast-forward ВМ до
   проверенного опубликованного commit, с сохранением локальных правил.
3. `.gitignore` не отслеживается и может конфликтовать с приходящим из Git.
   Перед обновлением прочитать/сохранить его отдельно, сопоставить правила и
   сохранить нужные локальные исключения. Не применять `git clean/reset --hard`.
   Не добавлять `.ipynb_checkpoints/` в публикуемый код.
4. По диску явного дефицита нет. CPU/RAM, данные, процессы,
   порты, зависимости, Gitea-доступ и manager сервиса ещё не проверены.
5. Следующий осмотр — read-only через доступный канал; затем согласованный
   main SHA, отдельное окружение, tests/CLI smoke и управляемый сервис по
   [плану main + ВМ](main_and_vm_release_plan.md).

В этой сессии инструменты не обнаружили подключённых браузерных вкладок.
Пользовательский локальный SSH-терминал не является инструментальной shell-сессией
агента. Для дальнейшей работы запрошен базовый URL JupyterLab без токенов;
пользователь передал базовую ссылку без токена. Попытка открыть JupyterLab
в управляемом браузере вернула `Browser is not available: iab`; альтернативный
Computer Use helper вернул `native pipe is unavailable`. Доступ к открытому
локальному SSH-окну не получен, команды на ВМ агентом не выполнялись.
До появления инструментального канала read-only проверки выполняет пользователь,
результаты агент анализирует; токены/пароли в чат не передаются.

## Выполненные пользователем команды установки Python

Способ сверён с официальными инструкциями Astral:
[установка uv](https://docs.astral.sh/uv/getting-started/installation/),
[путь установки и запрет правки shell profile](https://docs.astral.sh/uv/reference/installer/),
[managed Python](https://docs.astral.sh/uv/guides/install-python/).
Это пользовательская установка инструмента и интерпретатора, не установка
GoodsAI и не deployment. Git checkout и данные проекта не изменяются.

```bash
goodsai_uv_installer="$(mktemp)" &&
curl --proto '=https' --tlsv1.2 -LsSf https://astral.sh/uv/install.sh -o "$goodsai_uv_installer" &&
UV_INSTALL_DIR="$HOME/.local/bin" UV_NO_MODIFY_PATH=1 sh "$goodsai_uv_installer" &&
"$HOME/.local/bin/uv" --version &&
"$HOME/.local/bin/uv" python install 3.12 &&
goodsai_python="$("$HOME/.local/bin/uv" python find 3.12)" &&
"$goodsai_python" --version &&
python3 --version
```

Пользователь передал успешный вывод: uv 0.13.1, Python 3.12.15 по найденному
пути и прежний Python 3.10.12 для `python3`. Установлено только окружение
инструментов: это не подтверждение работоспособности самого приложения.
При повторении не отключать TLS и не продолжать после ошибки; точные версии
будущих установок могут отличаться, сохранять фактический вывод.

## Критерий успешного deployment — ещё не выполнен

Для нового окружения через uv использовать `uv venv --python 3.12 --seed .venv`,
если следующий шаг — `python -m pip install -e .`: seed обеспечивает pip.
Обычный `uv venv` без seed не гарантирует наличие pip. Исправление инструкции
не означает фактическую установку GoodsAI на ВМ.

Нужно зафиксировать реально запущенный commit из Gitea main, окружение,
успешные tests/smoke, управление процессом и проверку доступности по согласованному
контракту. Успешный пользовательский SSH-вход и диагностика диска этого не заменяют.
