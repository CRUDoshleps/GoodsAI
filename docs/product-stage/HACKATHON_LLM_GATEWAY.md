# Шлюз моделей хакатона: правила интеграции GoodsAI

Документ фиксирует технический контекст, показанный организаторами на обучающей сессии. Это не спецификация API: перед запуском команды проверяют доступность моделей и режим структурированного ответа на VM.

## 1. Что известно

- К моделям обращаются через хакатонный шлюз с интерфейсом, совместимым с OpenAI SDK.
- На выделенной VM параметры шлюза и ключ команды уже настроены: клиент создаётся через `OpenAI()` без аргументов.
- Ключ команды нельзя хранить во frontend, ноутбуке с выводом секретов или в Git-репозитории.
- Для обработки карточек требуется структурированный результат: минимум `attribute`, `value`, `confidence`. GoodsAI добавляет `evidence` и проверяет его своим кодом.

## 2. Роль моделей в каскаде

Выбор подтверждаем измерением на gold-set: названия ниже задают начальную гипотезу, а не обещание качества.

| Уровень | Инструмент | Когда используем | Что возвращает |
| --- | --- | --- | --- |
| 0 | Rules, словари, normalizer | Типовые единицы, бренды и числовые форматы | Кандидат со span и детерминированной причиной |
| 1 | Локальный дообученный encoder | Свободный текст в известных категориях | Кандидат-спан и score |
| 2 | `GigaChat3-10B-A1.8B` через шлюз | Массовые неоднозначные карточки, которые не прошли первые уровни | JSON-кандидат по схеме категории |
| 3 | `openai/gpt-oss-120b` через шлюз | Конфликт источников, редкая формулировка, новая категория | JSON-кандидат по схеме категории |
| 4 | Verifier и operator review | После любого модельного ответа | `auto_accept`, `review` или `abstain` |

`GigaChat3-10B-A1.8B` выбран как кандидат для массового слоя, потому что в материалах организаторов он указан для классификации и массовых запросов. `openai/gpt-oss-120b` — кандидат сильного слоя. Если измерения покажут, что local encoder лучше или дешевле на данном атрибуте, router оставляет encoder основным маршрутом.

## 3. Контракт модельного ответа

Модель не принимает решение о записи в каталог. Она возвращает только кандидата, строго подтверждённый текстом карточки.

```json
{
  "attribute": "storage_capacity",
  "value": "256 ГБ",
  "confidence": 0.95,
  "evidence": "встроенная память 256GB"
}
```

Пайплайн добавляет `source_field`, `model`, `prompt_version`, нормализованное значение, флаги проверки и финальное `decision`. Если `evidence` не находится в исходных полях, ответ становится `abstain`, независимо от confidence модели.

## 4. Адаптер и конфигурация

Интеграция изолируется за интерфейсом `ModelProvider`; бизнес-логика не зависит от конкретного провайдера или имени модели.

```python
class ModelProvider:
    def extract(self, text: str, requested_attributes: list[str], schema: dict) -> list[dict]:
        """Возвращает JSON-кандидаты, не финальные значения каталога."""
```

На VM клиент создаётся через `OpenAI()` без явного ключа. Вне VM параметры шлюза передаются только переменными окружения или защищённым secret store. В репозитории допускается только `.env.example` без значений.

```text
GATEWAY_FAST_MODEL=GigaChat3-10B-A1.8B
GATEWAY_STRONG_MODEL=openai/gpt-oss-120b
```

## 5. Проверки перед включением в маршрут

1. Проверить доступность имён моделей на VM и поддержку нужного формата JSON.
2. Сделать 10–20 коварных карточек: чужой бренд, конфликт title/description, `256GB`, `256 Гб`, `0.25 TB`, отсутствие значения.
3. Проверить, что модель не создаёт значение без text evidence.
4. Измерить valid coverage, precision `auto_accept`, LLM-call rate, токены, задержку и стоимость на 1 000 SKU.
5. Сравнить fast-model, strong-model и local encoder на едином gold-set по атрибутам.

## 6. Что не используем в MVP

Не добавляем RAG по всему каталогу, embeddings, Function Calling, агентов и Speech-to-Text: они не нужны для извлечения атрибутов из текстовых полей карточки и увеличивают сложность проверки результата.
