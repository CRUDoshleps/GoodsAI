## Следующий этап: VM и синхронизация

По сведениям пользователя, Linux VM имеет 2 CPU, 4 ГБ RAM, 32 ГБ диска;
проект находится в `~/project` с `.git`, `.gitignore`, `README.md`, `data/`,
`notebooks/` и `logs/`. Эти сведения в данной сессии не проверялись.
Проверяемая для сдачи ветка — `main` в Gitea.

Будущий процесс: локальная рабочая ветка → согласованные commit/push/PR →
проверка командой и слияние → обновление `main` на VM → запуск и проверка
через SSH или JupyterLab. Данные передаются отдельно от Git.

До автоматизации нужно проверить реальный remote, ветку, локальные изменения,
Python, зависимости, диск и расположение данных на VM. Будущий механизм
обновления должен сохранять данные и секреты, останавливаться при локальных
изменениях или расхождении истории, обновлять только согласованную версию
и не записывать секреты в лог. Не применять reset/clean для обновления.
Рабочий deploy-скрипт пока не создаётся. SSH-конфигурация не изменяется;
подключения и передача файлов на VM на текущем этапе запрещены.
