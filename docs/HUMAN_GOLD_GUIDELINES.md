# Инструкция независимому разметчику E1

Версия `human-e1-v1`, 19.10.2026. Политика наследует согласованные M2 решения;
новые runtime-правила этой инструкцией не вводятся.

## Как работать

Получите только свой локальный HTML-файл и эту инструкцию. Работайте независимо:
не используйте ИИ, интернет, предсказания GoodsAI, ответы другого разметчика или
готовые параметры из каталога. Разрешены только показанные title/description.
Не открывайте исходный HTML как страницу: он показан текстом и не исполняется.
Заполняйте все поля каждой карточки; не угадывайте по известной вам модели.
Сохраните скачанный JSON с ответами в закрытой папке вне Git. При перерыве
сохраните JSON и затем загрузите его в ту же форму. Автосохранения нет.

Знакомство с прежними development-примерами нужно честно указать; оно не
тождественно просмотру ответов для этих новых карточек. Если вы уже видели
именно эти карточки/ответы системы или обсуждали их с коллегой, сообщите об этом.
Разработчик не должен видеть reserve до фиксации проверяемого метода; после
просмотра нельзя подбирать метод или порог по этим ответам и называть такую
оценку независимой. Нужный доступ к текстам выдаётся координатором отдельно.

## Статусы

| Статус | Когда выбрать |
| --- | --- |
| `present` | Одно определённое значение прямо подтверждается разрешённым текстом |
| `absent` | В тексте нет сведений об этом атрибуте основного товара |
| `ambiguous` | Есть противоречащие значения, неизвестная роль/единица или неясная граница |
| `unjudgeable` | Текст повреждён/нечитаем или корректная оценка невозможна; объяснить причину |

Для `present` заполните каноническое значение, поле evidence и точную цитату из
исходного текста. Если цитата повторяется, укажите её начальную позицию в
Unicode code points (Python-индекс, не UTF-16). Форма показывает позиции начал
всех совпадений. Начальная/конечная позиция относятся к исходному HTML, не к
видимому тексту. Для остальных статусов значение/цитата/единица должны быть
пусты. Для ambiguous/unjudgeable обязательна заметка с причиной; можно
перечислить в ней противоречащие сигналы. Ненаписанное значение не выводится
из «здравого смысла». Сведения о чехле, совместимости или другом товаре не
относятся к основному товару.

## Поля и канонический вид

Смартфон: brand, model, storage_gb, ram_gb, screen_inches, battery_mah, color.
Чайник: brand, model, power_w, capacity_l, color.
Это текущая схема E1, не утверждение полного официального контракта всех категорий.

- **Бренд:** имя марки основного товара. При явном Xiaomi/Redmi используем более
  конкретный Redmi. Другие связи не достраиваем из знаний; бренд не дублируется в model.
- **Модель:** явно написанное коммерческое имя с линейкой/значимым индексом/5G,
  без бренда, памяти, цвета, состояния и отдельно перечисленных функций.
  Пробелы нормализуются; регистр и значимые символы сохраняются. Если основное
  имя однозначно, отдельный заводской код записывается в заметку. Если код —
  единственное имя, не отбрасываем его автоматически. При неясной границе — ambiguous.
  После `/` ничего не удаляем по общему правилу: роль суффикса должна следовать
  из разрешённого текста. Ненаписанные части имени не достраиваем.
- **Память:** GB, 1 TB = 1000 GB. `Gb` в согласованном контексте ёмкости памяти
  трактуется как GB. Одиночная ёмкость без явной роли RAM/storage — ambiguous.
  Явно подписанные роли и связная пара RAM/ROM с единицей допустимы. Пары без
  единиц, неизвестные роли и конфликты не разрешаем по величине чисел.
- **Числа:** строка с точкой, без лишних нулей: `6.5`, `1.7`, `5000`.
  Единицы: storage_gb/ram_gb — GB; screen_inches — inch; battery_mah — mAh;
  power_w — W; capacity_l — L. Не заменяем литры килограммами. Явно ошибочная
  единица/противоречие → ambiguous, а не молчаливое исправление.
- **Цвет:** русский канонический цвет/понятный оттенок: «черный», «лавандовый»,
  «серо-зеленый», «ультрамарин». Непонятный маркетинговый модификатор можно
  отбросить, если базовый цвет назван явно; полная фраза остаётся evidence.
  Единственный конкретный вариант можно предпочесть общей пометке «многоцветный»;
  вторую пометку сохраняем в заметке. Два конкретных противоречащих цвета → ambiguous.
  Материал корпуса не доказывает цвет. Явное имя варианта «титановый» допустимо.
  Цвет отдельных вставок не заменяет явно указанный основной вариант.

Новая спорная политика не утверждается разметчиком по одной карточке.
Отметьте ambiguous и опишите проблему координатору. Изменения инструкции
версируются до дальнейшей разметки; старые ответы не переписываются молча.
Числовая проверка наследует bounds текущего E1-контракта. Если верное явное число
не проходит её, не подгоняйте ответ: сохраните исходный ответ и сообщите
координатору. До решения SPEC/версии схемы такой пакет не превращается в gold.

## Независимость и итог

Два человека размечают одинаковые карточки раздельно. Только после фиксации обоих
JSON координатор сравнивает ответы. Третий человек разрешает расхождения;
если третьего нет, итог остаётся pending, а не автоматически «побеждает A».
Совпадение статуса/значения и совпадение evidence показываются отдельно.
Одна человеческая разметка полезна, но не закрывает требование двух независимых
разметчиков. AI-assisted и single-review наборы не называются независимым gold.
