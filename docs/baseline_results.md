## Производительность

Для основного полного запуска `predict`:

- CLI elapsed: **13,869 с**, около 744 карточек/с с чтением и записью JSONL.
- p50 времени обработки одной записи: **0,526 мс**, p95: **4,955 мс**;
  это внутренний таймер extractor/валидации, не сетевой SLA.
- Peak working set процесса: **31 166 464 байт**, около **29,7 МиБ**.
- Отдельная подготовка: **13,856 с**, peak working set **508 547 072 байт**,
  около **485 МиБ**. Включены проверка hashes и чтение Parquet.

Таймер CLI включает создание metadata, хеширование входа, чтение и запись
предсказаний; финальное хеширование выхода и запись manifest выполняются после
этого таймера. Память измерена через Windows API. Значения — локальные снимки,
они зависят от оборудования и нагрузки; CPU и RAM VM этим не измерялись.
Extractor последователен, Parquet читается с `use_threads=False`.

## Оценка качества и ближайшая работа

P/R/F1: **N/A**. Ручная разметка пока не выполнена. Evaluator, запущенный на
120 пустых заданиях, вернул `no_judged_manual_labels`, `pending_cards=120` и
null для precision/recall/F1. Эти пустые задания не выдаются за gold-set.

Подготовлены 120 заданий: 30 development и 30 validation на каждую категорию,
поровну с описанием и title-only. 5 383 связанные группы распределены целиком;
все группы с EDA-выборкой относятся к development. Ещё 1 616 SKU зарезервированы
для будущего test, но до проверки near-duplicates и ручной разметки этот резерв
нельзя считать готовым независимым тестом.

Самые полезные следующие шаги к 23 октября:

1. Заполнить задания вслепую, часть разметить независимо вторым человеком,
   разрешить расхождения и получить validation-таблицу по атрибутам.
2. Разобрать ложные/пропущенные кандидаты. Улучшить контекст и нормализацию;
   проверить недостающие бренды чайников, не извлекая словарь из закрытого test.
3. Добавить консервативное извлечение модели товара; расширять только методы,
   чьи правила и ошибки понятны по development/validation.
4. Зафиксировать final test, затем отдельно согласовать сравнение с ML/LLM
   на тех же карточках. Измерить добавочный recall, FP, время и стоимость.
5. Уточнить required attributes/справочники и формат сдачи; отдельно проверить
   воспроизводимость на Linux/VM при получении разрешения.

VM, внешние сервисы, платные LLM и обучение моделей в этой итерации не использовались.
Коммит, push и merge не выполнялись.
