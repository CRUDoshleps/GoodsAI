## Решение и границы гарантий

1. Уникальный tempfile рядом с целевым файлом, flush/fsync, затем os.replace.
   Исключение до замены сохраняет предыдущий файл и убирает свой tempfile.
2. Неблокирующая OS-блокировка каждого назначения: второй писатель получает
   понятную ошибку, разные назначения не мешают друг другу. Блокировка снимается
   ОС при гибели процесса, оставшийся lock-файл не означает занятую блокировку.
3. Для predictions/manifest — общий захват обеих блокировок, staging новых
   файлов и журнал восстановления с резервными копиями старых. Подтвердить
   публикацию только после обеих замен; при обычном сбое откатить обе.
4. После принудительного завершения восстановить незавершённую публикацию при
   следующем обращении через поддерживаемый reader/writer. Reader проверяет SHA
   manifest перед использованием результатов. Старые predictions без manifest
   остаются поддержаны как standalone JSONL, не как проверенная пара.
5. Проверить на отдельных процессах конкуренцию, аварийное завершение между
   заменами, восстановление и согласованность; прогнать baseline и reader suites,
   demo и CLI smoke. Обновить README/индекс/статус, сохранить commit/push.

Два обычных файла нельзя заменить одной атомарной операцией. Пока writer
работает, произвольный внешний reader без блокировки может увидеть переходное
состояние. Гарантии относятся к нашему reader/writer; стороннему потребителю
нужно использовать reader или проверить SHA и отсутствие pending transaction.
Журнал/lock-файлы — служебные артефакты, не новый prediction-контракт.
Отключение питания и неподдерживаемые/сетевые файловые системы отдельно не проверены.

## Критерии готовности

- Параллельная запись одного назначения отвергнута, разные output работают.
- При исключении прежний результат цел, чужие временные файлы не затрагиваются.
- Ошибка после первой замены откатывает обе; после kill повторное обращение
  восстанавливает корректную старую пару, блокировка не остаётся занятой.
- Ошибка/недоступность восстановления не превращается в успешный пустой результат.
- Несовпадающий SHA manifest отвергнут при чтении; схема v0.1, правила и метрики
  не меняются. Реальные данные/reference не перезаписываются.
- В Git только код, синтетические тесты и документы; перед каждым merge повторно
  проверить ветки/PR, при новых ветках коллег остановить merge и уведомить Влада.
