## Живой показ: предлагаемые 5–7 минут

| Фрагмент | Что показываем | Что должно быть видно |
| --- | --- | --- |
| Вход | Новая синтетическая карточка через текущий API/CLI | Только title/description, категория; нет target hints |
| Успешный случай | Извлечение brand/model/ключевых характеристик | Canonical value, unit, raw evidence/offsets, heuristic score, review |
| Пограничный случай | Конфликт или отсутствующая характеристика | abstain и reason, без выдуманного значения |
| Верификация | Неподтверждённый/чужой факт и корректный факт рядом | Плохой кандидат отклонён, допустимый факт сохранён |
| Сохранение | Файл predictions и manifest, verification | Hashes, run identity, повторяемость результата |
| Итог | Реальные измерения и ограничения | Catalog-silver, reviewed development и synthetic QA разделены |

Для репетиции переиспользовать прошедшие внешние кейсы постоянных ID из
`scenario_cases.py`/`external_cases.py`; runtime должен обрабатывать введённый
текст, а не возвращать заранее сохранённый ответ. Packaged demo показывать
как отдельный smoke, а не доказательство качества всего каталога.

Основной показ должен запускаться без платных model calls. Для отдельного
живого LLM-показа нужны согласованные доступ, бюджет и разрешение на вызов.
Fake/loopback tests подписывать именно как проверки интеграции и отказов.
Наличие LLM route не означает, что текущий default runtime использует LLM.
Эксперимент PR #136 показывать с его реальным keep/drop и границами оценки,
не объявлять непринятый компонент работающей частью финального main.

Резерв при проблеме удалённой ВМ — локальный CLI/API на том же опубликованном
коде с новым synthetic входом. Предварительно сохранённый протокол помогает
объяснить сбой, но не заменяет требуемую живую демонстрацию.

## Слайды: предлагаемая структура

1. Задача и пользователь: зачем нормализованные атрибуты нужны поиску/фильтрам.
2. Основной путь и короткий вход/выход с evidence и review/abstain.
3. Архитектура: rules → optional model/LLM → общий verifier → результат/manifest.
4. Безопасность результата: exact evidence, нормализация, конфликты, отказы,
   schema limits, budgets/timeouts/cache; heuristic confidence не вероятность.
5. Метрики: per-attribute/category, поддержка и exclusions; сравниваемые
   версии и reference. Использовать `reports/quality_20261021.*` и принятый
   результат #136; ссылки на hashes, не непроверенные цифры из старых слайдов.
6. Реальное развитие методов: что добавили правила/модель/LLM и какой route
   оставили/отклонили по измерениям. Невыполненные сравнения обозначить N/A.
7. Воспроизводимость: README, существующие commands, CI, artifacts и final
   release record. Synthetic bundle не называть финальной поставкой на данных.
8. Риски и следующие шаги: новые категории, noisy labels, независимая оценка,
   calibration и стоимость. Возможное объединение со слайдом 7 при коротком слоте.
