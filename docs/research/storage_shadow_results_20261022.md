## Запуск и повторение

Протокол и инструменты нужно заморозить commit до запуска; изменение их bytes
после freeze требует нового пакета. Старые пакеты не переписываются.

```bash
python -m scripts.research.storage_shadow prepare \
  --bundle outputs/private-catalog-silver-bundle \
  --seen data/gold/prior-reviewed.jsonl \
  --output-dir outputs/storage-shadow-new

python -m scripts.research.storage_shadow assess \
  --bundle outputs/storage-shadow-new \
  --answers /private/path/answers-storage-shadow.json \
  --output-dir outputs/storage-shadow-human-new
```

`--seen` повторяется для **всех** известных ledgers прежней разметки/AI-просмотра.
Это обязательная часть реального протокола, не только переданный пример одного
файла. Все их hashes сохраняются до отбора. Случаи с metadata.exposed также
исключаются всем семейством. Нельзя считать отсутствие одного SKU достаточным
доказательством непросмотренности остальных вариантов семьи.

В `review.html` локальная форма на основе существующего human_gold_form.html:
в ней нет сети, каталогового ответа или автоматической human-подтверждённости.
Статус каждого случая нужно изменить вручную. Сохранить JSON кнопкой перед
закрытием; возможен импорт предыдущего JSON. Альтернатива: партии `review-*.md`
с постоянными ID и явным подтверждением человеком просмотренного диапазона.

`assess` принимает неполностью просмотренный пакет с unreviewed, но возвращает
pending и N/A для итоговой границы. Неоднозначные/неоцениваемые случаи не
исключаются из знаменателя, а показываются отдельно и считаются ошибками для
консервативной оценки. Сам отчёт не даёт права менять runtime.
