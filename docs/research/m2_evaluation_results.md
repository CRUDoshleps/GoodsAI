# M2: расширенный reviewed development и результат M1

18 октября 2026 года. Development-часть M2 завершена: 20 новых карточек
проверены человеком по [согласованной политике](m2_annotation_policy_v2.md)
с уточнением неизвестных слэш-суффиксов. Runtime M1 не менялся.
Подготовка/seed/quarantine — [протокол M2](m2_evaluation_preparation.md).
Это **AI-assisted human-reviewed development**, не независимый holdout.
Резерв test из 40 карточек остаётся закрытым для текстового анализа/предсказаний.

## Разбор ошибок и следующие задачи

Все локальные TP/FP/FN/исключённые выдачи доступны по постоянным review_id
в diagnostics.jsonl; реальные тексты/имена не публикуются в этом отчёте.

Семь model-FN сопоставлены с кодом model_rules.py:

| Форма | Количество | Наблюдение по коду |
| --- | --- | --- |
| Имя с цифры, затем буква | 1 | IDENTIFIER принимает буквенный CODE либо только цифры; такая смешанная форма не завершается корректно |
| SIM-конфигурация после имени | 1 | tail_is_boundary не распознаёт этот хвост |
| Пара памяти без единиц после имени | 1 | Не проходит QUANTITY boundary; саму память по инструкции не угадывать |
| Цвет + фактура | 1 | После известного цвета остаётся непустой непринятый хвост |
| Запятая перед объёмом | 1 | QUANTITY проверяется до удаления запятой, повторной проверки меры нет |
| Линейка перед индексом | 1 | Намеренный отказ при дополнительном слове между известным брендом и индексом |
| Квалификаторы после индекса | 1 | Не распознаются как безопасная часть коммерческого имени/граница |

Это наблюдения, не разрешение автоматически расширять grammar. Любое изменение
проверять на новом фиксированном dev с сохранением старых TP и диагностикой FP.

Три неверных заполнения: два brand из-за выбора родительского/сокращённого
написания вместо согласованного канона; один color теряет точный оттенок.
Ещё четыре brand-FN — отсутствие явно написанных марок в словаре. При этом
неизвестный бренд не всегда блокирует model: не объяснять все model-FN словарём.
Незаполненные поля: три battery-FN с формой единицы со звёздочкой, один RAM-FN
для пары с двумя единицами, один screen-FN с коротким локальным контекстом,
два capacity-FN из-за контекста/ограничения «до», один storage-FN с конфликтующим
объёмом внешней карты. Три пропуска цвета — неподдержанные имена/оттенки.

Приоритеты без расширения M2:

1. В отдельном согласованном инкременте устранить default роли памяти и
   проверить соответствие утверждённым brand/color-политикам. Нужны новые
   синтетические проверки и парная оценка, не тихая смена уже frozen C.
2. Дешёвые явные единицы/форматы и точечные границы имён — отдельные малые
   изменения по development; не большой универсальный verifier-refactor.
3. M3: реальный model fallback на оставшихся сложных границах/линейках,
   общий router/verifier, C/D на том же reference и учёт цены. Он не исправляет
   автоматически brand/color FP. Шлюз, расходы и данные требуют разрешения;
   в M2 реальных модельных вызовов нет. Заглушка адаптера не закрывает R7.
4. После заморозки сравниваемых методов — слепая человеческая разметка 40 test,
   отдельный финальный прогон без подбора правил. Этот долг остаётся открытым.

Для ревью организаторов M2 добавляет воспроизводимые доказательства R2/R6/R9,
выявляет пробелы R4/R5, но не закрывает модельный слой R7 и независимую оценку.

## Производительность, цена и проверки

Windows 11 / Python 3.12.6, три свежих isolated worker-процесса на вариант,
по 20 одинаковых карточек. Все три файла predictions каждого варианта побайтово совпали.

| Вариант | Медиана extractor p50 | Диапазон extractor p95 | Медиана batch |
| --- | --- | --- | --- |
| A | 0,314 мс | 2,305–2,490 мс | 175,6 мс |
| B | 0,357 мс | 2,461–2,918 мс | 175,9 мс |
| C | 0,893 мс | 2,689–3,091 мс | 179,0 мс |

Batch включает служебную работу/запись, отдельный process wall-time включает
startup (~0,46–0,52 с). C batch throughput ~109–113 карточек/с, peak RSS ≤35 MiB.
Это описательная оценка маленькой партии; первые записи в свежем процессе
не являются строго прогретым benchmark. SLA/каталожную пропускную способность
и стоимость масштабирования из этого не выводить.
LLM calls=0, tokens=0, API cost=0 ₽ во всех A/B/C.

69 tests прошли (включая 7 sampling/review и 3 новых summary tests).
Canonical evaluator и postprocessor совпали по judged TP/FP/FN/P/R/F1.
SHA reference/selection/старых snapshots проверены; test тексты не открывались.
Linux/ВМ не проверялись в M2. Commit/push/merge не выполнялись.

Фактический запуск выполнен один раз по команде:

```powershell
.\.venv\Scripts\python.exe scripts/research/compare_model_stage.py `
  --gold data/gold/e1/m2/v2/reviewed/development.human-reviewed.jsonl `
  --split development --baseline-ref 5f77d81 --repeats 3 `
  --output-dir outputs/experiments/model-stage/m2-reviewed-development-v1
.\.venv\Scripts\python.exe scripts/research/summarize_m2.py `
  --experiment outputs/experiments/model-stage/m2-reviewed-development-v1 `
  --bundle data/gold/e1/m2/v2 `
  --output outputs/experiments/model-stage/m2-reviewed-development-v1-slices-v2
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для повтора выбрать **новые** output-dir/output; существующие защищены от
перезаписи. Baseline ref и текущий src должны соответствовать frozen identity;
после смены runtime сравнение — новый явно названный эксперимент.
