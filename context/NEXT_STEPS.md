# Следующие шаги — коротко

Цель: продуктовый чекпоинт 15 октября. На скриншоте указан старт 17:00, но команда выступает в индивидуальный слот. Уточнить слот и часовой пояс расписания.

## До встречи

1. **Зафиксировать одну фразу о продукте.** GoodsAI помогает контент-оператору заполнять пропущенные характеристики по тексту карточки и проверять спорные значения по исходному фрагменту.
2. **Сузить демонстрацию.** Предлагается категория «Смартфоны» и 3–5 полей: бренд, модель, память, цвет, диагональ. В архиве 7 988 смартфонов; для показа достаточно 10–20 выбранных карточек. Это демонстрационная категория, не весь целевой каталог.
3. **Подготовить три исхода.** Значение найдено и нормализовано; источники расходятся; значения в тексте нет. Для каждого показать понятный результат и действие оператора. Дополнительно полезен пример «чехол для Samsung», где совместимость не означает бренд товара.
4. **Сделать связный показ в существующем макете.** Выбор карточки → исходный текст → предложенные атрибуты и цитата → принять/исправить/отклонить. Если это постановочный сценарий, явно отметить демо-данные. Небольшой парсер на правилах — усиление при наличии времени, не обязательный барьер для встречи.
5. **Убрать противоречия в рассказе.** Не обещать обязательный полный каскад; исправить пример координат evidence и атрибуцию статьи; не называть вымышленные проценты уверенностью работающей модели. Подробности в AUDIT.md.
6. **Отрепетировать короткую защиту и вопросы.** Пользователь, боль, сценарий, ценность, ограничения, план проверки. Содержание собрано в CHECKPOINT_BRIEF.md; длительность выступления сверить с регламентом.

## Что считать достаточным результатом подготовки

Эксперт понимает, для кого продукт, видит один целый сценарий и ограничения, понимает, что уже реализовано и что только планируется. Есть объяснение, как позже будут измеряться точность, полнота и сокращение ручной работы. Это наш критерий готовности к разговору, не пересказ неизвестного официального рубрикатора.

## После обратной связи

1. Уточнить обязательные поля и правила оценки у организаторов; проверить соответствие параметров каталога будущим целям.
2. На небольшой выборке связать каталог и описания по SKU, убрать целевые атрибуты и их алиасы из входных полей, подготовить ручную проверку и разбиение без утечки дублей.
3. Реализовать rules baseline с нормализацией, evidence и метриками.
4. Сравнить с одним ML- **или** LLM-подходом. Выбирать следующий компонент по результатам, а не по размеру схемы архитектуры.
5. К финалу собрать шесть артефактов из PDF, стр. 18. Дата финала здесь не установлена.

До чекпоинта не требуется обрабатывать весь архив, обучать encoder, строить трёхступенчатый каскад, кабинет продавца, мониторинг и автоматический retrain. Срок сдачи финала, ресурсы и разрешённые API остаются неизвестными.
