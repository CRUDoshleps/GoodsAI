## Схема каталога

`yml_catalog → shop → offers → offer` — список товаров. У товара есть `@id`, `@available`, `name`, `categories.categoryId`, `param`; почти у всех также `vendor` и `model`. Категории находятся в `shop.categories.category`, с ID, parent ID и названием. Внутренняя дата каталога: `2026-05-13T03:00:00+0000`.

Параметры имеют поля `@name`, необязательное `@unit`, `#text`. Контейнер `param` — список у 546 040 товаров и одиночный словарь у 29: загрузчик должен поддержать оба варианта. Некоторые имена повторяются с разными значениями; преобразование в обычный dict с одним значением потеряет информацию.

## Что это меняет в прототипе

1. Реальные карточки для показа уже доступны; искать ещё один большой датасет не нужно.
2. Для первой демонстрации достаточно одной категории; расширение на остальные категории — следующий этап.
3. Параметры каталога могут помочь подготовить примеры, но не являются автоматически ручным gold-set.
4. Для восстановления пропущенного атрибута нельзя подавать в извлекатель тот же атрибут среди seller fields. Маскировать нужно и прямое поле, и эквивалентные/производные алиасы. В смартфонах встречаются, например, «Встроенная память», «Встроенная память (ROM)_search», «Оперативная и встроенная память_search». Простого удаления суффикса `_search` недостаточно.
5. Поисковые события не нужны для показа основной ценности. Их можно изучить позже для приоритизации, не обещая сейчас доказанный бизнес-эффект.

## Что осталось неизвестным

Покрытие объединения по `sku_id`, дубли и пропуски в описаниях, расхождения title/name, точная семантика поисковых событий, обязательные поля, качество gold-разметки и официальный split. В ZIP только три перечисленных файла: отдельной инструкции или manifest обязательных полей нет. Из этого нельзя заключить, что организаторы не выдали их отдельно.

Описания и каталог имеют разное число строк. Для последующего прототипа их связывают по проверенному SKU ID, не по позиции строки; типы ID необходимо согласовать. `sku_subject_id` и `sku_seo_id` нельзя без проверки приравнять к `categories.categoryId`.

Установка pyarrow и дальнейшее чтение Parquet были остановлены после уточнения пользователем объёма задачи. Временные распакованные файлы находятся в `/tmp/goodsai-data-audit`; это рабочий кэш, не постоянная часть репозитория. Полный EDA, модельные метрики и joined dataset не созданы.
