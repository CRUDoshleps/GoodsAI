# Следующие шаги

Текущая цель — продуктовый прототип. По скриншоту пользователя чекпоинт 15.10 в 17:00; у команды индивидуальный слот. Его точное время и часовой пояс подписи нужно сверить с организаторами. Дата финала здесь не установлена.

## Сейчас

1. Выбрать концепцию A: помощник контент-оператора. Пакетную обработку B оставить небольшим способом ввода/вывода; C и D — будущими направлениями.
2. Зафиксировать одну категорию и 3–5 характеристик. Смартфоны удобны для демонстрации, но не представляют весь каталог.
3. Подготовить небольшой набор карточек: однозначное значение, нормализация, конфликт, отсутствие значения, совместимость с чужим брендом. Проверить ожидаемые ответы вручную; изменённые и синтетические примеры пометить.
4. Показать полный сценарий на существующем экране: открыть карточку → увидеть предложение и цитату → подтвердить/исправить/отклонить. Статический показ допустим как концепт; интерактивность или небольшой rules extractor добавлять, если это помогает встрече и укладывается во время.
5. Уточнить презентацию: возможности прототипа отдельно от целевой архитектуры; убрать обязательность полного каскада, необоснованные проценты, неоднозначный пример единиц и гарантии эффекта для поиска/продаж. Использовать короткую формулировку из CONCEPTS.md.
6. Вынести экспертам вопросы: основной пользователь, наиболее дорогие ошибки, обязательные поля, официальный формат оценки и ожидаемый следующий артефакт.

Критерий готовности к обсуждению: эксперт понимает проблему, пользователя, один сценарий, ограничения и способ последующей проверки пользы. Это рабочая рекомендация, не неизвестный официальный рубрикатор.

## После чекпоинта

1. Подтвердить доступ к полному архиву через LFS и зафиксировать требуемые атрибуты; для прототипа работать с небольшим срезом.
2. Проверить join каталога/описаний по SKU, качество разметки, алиасы и дубли. Не начинать с обработки всех 31 млн строк query_clicks.
3. Реализовать и измерить baseline: извлечение → нормализация → проверка → результат.
4. Сравнить с одним ML- или LLM-подходом на фиксированном наборе. Полный каскад добавлять только по результатам сравнения.
5. До финальной сдачи подготовить воспроизводимый запуск и предусмотренные кейсом артефакты. Не смешивать эту готовность с готовностью концептуального показа.

## Что не требуется сейчас

Полноценный кабинет продавца, seller score, приоритизация по реальному спросу, API production-каталога, автоматический retrain, обучение нескольких моделей и отдельный мониторинг. Не скачивать и не прогонять весь архив только ради демонстрации продуктовой идеи.
