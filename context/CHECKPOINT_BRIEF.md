# Продуктовый чекпоинт: содержание показа

Статус: рекомендованный сценарий подготовки на 15 октября; не официальный перечень требований. Это текстовая заготовка, не готовая презентация и не реализованное демо.

## Продуктовая гипотеза

Контент-оператор тратит время на поиск характеристик в свободном тексте. GoodsAI предлагает нормализованные значения вместе с фрагментом-основанием, чтобы оператор мог быстрее заполнить карточку и проверить неоднозначность. Потенциальный эффект — более полные характеристики и меньше ручного поиска; влияние на поиск, конверсию и GMV ещё не измерено.

## Примеры для показа

Это специально составленные примеры для объяснения сценария, не строки датасета и не результаты извлечения.

| Вход | Что нужно объяснить |
| --- | --- |
| «Смартфон Brand X, 256GB, чёрный» | Память приводится к «256 ГБ», источник выделяется в тексте |
| Заголовок: «чёрный»; описание: «белый» | Есть конфликт: предложить проверку, не выбрать цвет автоматически |
| «Смартфон Brand X» без информации о батарее | Батарея остаётся незаполненной; отсутствующий факт не дополняется догадкой |
| «Чехол Brand Y, совместим с Samsung» | Samsung относится к совместимости; простого совпадения слов недостаточно |

Если нужны реальные карточки для показа, выбрать небольшую выборку из архива и вручную проверить значения. Изменённые для демонстрации конфликта карточки пометить как модифицированные.

## Короткое объяснение подхода

«Сначала мы проверяем, можно ли извлечь характеристику из текста и привести её к единому формату. Для оператора сохраняем источник значения. Надёжный результат можно подтвердить, конфликт нужно проверить, отсутствующее значение остаётся пустым. Первый работающий вариант строим на правилах, затем сравним с модельным подходом на одинаковых данных».

## Ответы на вероятные вопросы

- **Что уже работает?** Сейчас есть документация и статический концептуальный экран. Архив получен и предварительно изучен; модель не обучена, извлечение не измерено.
- **Зачем это, если в каталоге уже есть параметры?** Извлекать нужно пропущенные поля. Заполненные параметры — кандидат на слабую разметку, но в проверке восстановления целевое значение и его алиасы удаляются из входных структурированных полей. Иначе получится копирование готового ответа.
- **Почему не обязательно три модели?** На первом этапе важнее проверить полезность сценария и качество baseline. Затем достаточно одного сравнения с ML или LLM; более сложный каскад требует обоснования.
- **Почему не доверять любой цитате?** В тексте встречаются совместимость, отрицания и свойства комплектующих. Источник нужен для проверки, но сам по себе не гарантирует правильный атрибут.
- **Как поймёте, что есть польза?** На размеченной выборке измерим precision/recall/F1 по полям и покрытие; с оператором — время проверки и долю исправлений. Рост GMV заранее не обещаем.
